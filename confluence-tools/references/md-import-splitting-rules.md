# Markdown 页面容量与均衡拆分

## 强制读取条件

助手执行 Markdown 单页、目录导入或恢复计划前，必须完整读取本文件。
由 SKILL.md 直接路由；读取后在公开回执中说明输入范围、全目录评估和原件保护边界。
本文件规定助手工作流，不声明 md_import.py 已支持自动拆分，不增加 CLI 或配置键。

## 范围与计数

- 全量评估用户指定范围内的所有待上传 Markdown，包括前置内容、各章和附录；不得只处理
  最长文件后就跳过其他文件。全部评估和必要处理完成后，才生成最终上传计划。
- 默认采用约 15000 的内容量作为初始篇幅参考；先声明单位，用户指定的统计口径优先。
  Typora 的“词”和“字符”不能混用。源码字符包含 LaTeX 和 Markdown，不是文件字节数。
- 使用 Typora 词数时，记录版本／算法或实测依据；程序根据 Markdown 提取文本得到的值，
  未经编辑器逐文件对照时标为估算。误差可能改变是否拆分或页数时，先核对再落地。
- 同时报告源码字符、行内公式、块公式和图片引用数。不能把格式 CLEAN 当作容量通过。
- 公式密集程度参与边界选择；没有实测依据时，不设定或声称统一的公式数量安全上限。

## 内容边界与均衡

1. 建立按原文顺序排列的安全切分点，优先使用章内小节标题，其次使用下级标题。
2. 根据总量和参考容量确定合理页数，再在安全边界上平衡各页内容。约 20000 的文档优先
   拆为约 10000 + 10000，避免机械形成 15000 + 5000；允许为内容完整性保留合理差异。
3. 保持公式环境、代码围栏、表格、列表项完整；例题与解答、证明、图片与图注尽量同页。
   一个不可分单元过大时，明确报告；不得在公式中截断或为了达标删除正文。
4. 检查公式数量是否明显集中在某段，必要时沿下级标题进一步均衡；记录取舍和最终范围。
5. 保持原书小节、图表和公式编号以及正文顺序；不改写数学含义。新增页标题和必要的上下文
   提示单独记录，不能计作原文内容来掩盖遗漏。

## 副本与文件

- 沿用导入预审的原件保护、完整副本和重名处理规则。格式无需修复但需拆分，同样进入副本阶段。
- 已有副本不能因为文件名含“修复”就自动获得覆盖权限；沿用已获授权的准确范围，保存变更前备份。
- 初始副本包含完整输入。分段放回同一上传目录时，可共用原 .assets 目录；每个引用必须相对
  实际 Markdown 可解析。上传时每页具备其引用所需的附件，不依赖另一个页面偶然存在附件。
- 将完整旧章节备份放在上传范围之外，避免整章和分段一起被扫描上传；不要在 logs 中放上传候选。
- 如原标题为“第NN章 主题”，分段使用“第NN-1章 主题”“第NN-2章 主题”；其他标题使用
  “原标题（1）”“原标题（2）”。用户指定标题或层级优先；原书正文编号保持不变。
- 分段默认沿用原页面的父级。只有用户指定时才增加章节容器页。
- 保存副本外的清单：源相对路径和哈希、统计口径、分段标题、原文范围、文件哈希、附件和链接映射。
  重跑先读取清单并检查哈希，不把分段当新章节再次拆分或重复添加分段编号。

## 预审、计划与上传

- 先复审全部受影响文件，再审核最终目录全部 Markdown；执行公式、XHTML、附件和文件哈希门禁。
- 页面树和上传计划以最终文件为准；保留已批准的首页合并、标题和层级，不因目录名改变意外加页。
- plan-only 保持只读，可输出容量报告和拟拆分清单；不创建副本、拆文件或写服务器。
- 已存在远端章节时，先保存 ID、版本、正文、父级、附件及链接。明确第一段是否复用原 ID，
  其余段如何新建；按批准的映射更新，不依赖改名后的模糊标题查找，不自动删除旧页或附件。
- 先上传所有分段内容并验证，再更新书籍目录。调整本次范围内的章节、小节和跨页引用；
  锚点以服务器实际渲染的 ID 为准。范围外的旧深链接不作自动有效的保证。
- 恢复执行必须使用与最终分段文件一致的计划；旧计划哈希或文件集合不匹配时重新预审规划。
- 单文件拆为多页后按多页计划逐项执行，不能把全部段落回写同一 page ID；同一 ID 不得分配给多个分段。

## 验收与完成

- 本地逐段拼回正文，剔除明确记录的新增标题后，与拆分前内容逐字／哈希核对；公式和图片引用
  顺序也必须一致。附件文件校验哈希，不用“数量相同”代替内容完整性。
- 远端逐页核对标题、ID、父级、版本、数学宏和图片引用，确认所有计划页面及目录目标存在。
- 报告未拆、已拆、超参考容量的文件及原因；任一必要页面、附件或链接失败时不能宣称完整成功。
- 内容与结构校验不等于浏览器效果或性能验证。用户自行验收效果时，不代做加载测速或浏览器
  渲染测试，也不将这些测试作为上传完成条件；如实列出尚未验证的效果范围。

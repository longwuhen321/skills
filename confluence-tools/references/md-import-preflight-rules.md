# Markdown 导入预审规则

## 强制读取条件

仅在最终生效的 `preflight_review` 为 `true` 时，必须在任何远端写入前完整读取本文件；
关闭预审时不读取。读取后在公开回执的“已完整读取”中列出本文件，并声明预审失败时
零远端写入。

## 执行契约

1. 在任何页面、附件查询或写入前，只读预审用户指定对象中的全部 Markdown；预审期间
   复核对象哈希，发现原件变化立即停止。
2. 每个文件明确返回三态：`CLEAN` 表示无需修改，`FIXABLE` 表示存在可确定修复项，
   `BLOCKED` 表示需要人工判断或缺少附件等条件。
3. 全部为 `CLEAN` 时直接上传原文件或原目录，不创建副本；上传前再次核对最终审核对象
   的文件哈希。
4. 发现任一 `FIXABLE` 或 `BLOCKED` 时，保持原件字节不变，在同级创建一次完整修复副本：
   单文件使用 `<原文件名不含扩展名>__修复.md`，目录使用 `<原文件夹名>__修复`。
   目录必须完整复制，副本内部所有文件、附件、子目录、名称和层级初始保持一致；只改变
   最外层目录名。
5. 默认修复副本已存在时不得静默覆盖，必须询问用户选择覆盖、改用另一个同级名称或取消。
6. 只在修复副本中应用确定性修复或人工修改。先复审最初及后续发现的全部问题文件；
   它们全部通过后，才全量复审整个副本目录。全量复审发现新问题时回到问题文件复审，
   直至两级审核均通过。
7. `__修复` 仅是本地对象标识，不改变 Confluence 页面标题。修复状态写在副本旁边的
   `<副本名>.confluence-review.json`，不插入副本目录，因此不改变待上传目录内部结构。
8. `logs/intermediate/<时间戳>/<任务标识>/` 只保存 `review.json` 和 `manifest.json`
   等报告；不保存、也不把日志中的 Markdown 当作可编辑上传对象。成功报告移入
   `logs/_archive/`，失败报告保留供排查。
9. 单页或树在最终全量审核及哈希门禁通过前，禁止执行任何远端写入。

## 阻断规则

- 拒绝非 UTF-8、NUL 字符和内部占位符残留。
- 拒绝无法安全识别或未配对的 `$...$`、`$$...$$` 和 `latex` 围栏。
- 拒绝公式内明显不平衡的花括号和不配对的 `\begin{...}` / `\end{...}`。
- 拒绝不存在的本地附件；HTTP、协议相对、`data:` 和页内引用不作本地检查。
- 拒绝转换后不平衡的 storage XHTML。
- 拒绝公式数量与 `mathinline` / `mathblock` 宏数量不一致。
- 拒绝转换后仍有正文公式、内部占位符或数学宏内 `em` 标签残留。

## 确定性修复

- 把对称空格行内公式 `$ x $` 规范化为 `$x$`。
- 单边空格公式仅在内容具有强数学特征时修复，包括 LaTeX 命令、上下标或两侧有操作数的算术运算；只修改修复副本。`$ x$`、`$x $` 等含义不明确的写法继续阻断，避免误伤 shell 变量和金额。
- 把明确位于公式内部的 `<em>...</em>` 恢复为 LaTeX 下划线。
- 把未定义控制序列 `\*` 规范化为 `*`。
- 不猜测未知 LaTeX 命令，不改写公式语义。

## 审核报告

读取失败报告时按 `状态 + 规则 ID + 行列 + 消息` 定位。只有问题文件复审通过、最终
全量复审通过、`storage_validation.passed=true` 且上传对象哈希未变化，才允许继续上传。
不要通过忽略报告、直接改 manifest 或修改状态文件绕过门禁；需要绕过整套预审时，
必须由用户显式关闭配置或使用 CLI 覆盖。

任务结束后按规则 ID 复盘：可跨文档稳定修复的内容归为通用问题，建议固化到审核或转换
脚本并增加回归测试；仅当前文档成立的内容归为个例，先询问用户是否记录到问题库，供下次
遇到同类问题时检索借鉴。
